# M10：M7–M9 合并后的真实验收准备

状态：harness 已补断言，尚未运行新真实 Komodo 测试。M6 历史成功证据不能覆盖
M7–M9的新路径；普通假后端测试也不能替代这一轮真实验证。

## 本轮最小验收

沿用四服务样例、8个固定测试/临时生产角色资源与 v1/v2/bad 镜像：

1. 真实资源目录建立后，从浏览器重复读取8资源及 Core 缓存，核对固定ID、完整
   配置匹配、缓存状态与查询次数。每次均保持发布记录、配置写入数和Deploy数不变
2. 打开执行确认，核对真实目标ID与不可变镜像；取消不写记录/配置/Deploy。
   第二标签改变候选后，旧确认被拒绝，再恢复v1候选
3. 四服务按原流程测试、验收、晋级v1、更新v2、回滚v1。测试阶段先通过新诊断
   读取真实Update/配置/容器健康，等到符合核对条件，同时断言没有记录结果；
   然后才由原核对流程重读并写入结果
4. 坏镜像的真实非OOM、非暂停、退出1证据先由诊断确认，再由原流程记录失败，
   阻止验收/晋级，临时生产角色仍保持v1
5. 保留已知回执重启核对、未使用验收撤销及故意丢弃真实Deploy回执的原测试。
   历史结果/unknown诊断不得发远端读取；最终8资源检查也不能解除unknown阻断
6. 查看桌面/390px手机截图，验证正常结束和失败路径清理，并记录实际源码SHA

此轮不为每个合成故障重新制造真实基础设施故障。HTTP取消、超时、错配等分支
已有普通测试，真实harness重点覆盖当前API/资源/容器链路。浏览器的测试验收
仍为合成操作者点击，不代表生产身份验证或用户最终功能意见。

## 执行前必须明确批准的动作

仅为本轮在GitHub临时Linux runner运行受审源码：启动Komodo Core 2.3.3、Mongo
8.0与Periphery，把该临时机Docker socket交给Periphery，生成本次随机测试登录/
数据库/JWT等凭据，并运行上述固定样例部署/更新/失败/回滚及只读检查。

Docker socket可管理该临时机容器，不是仅几个样例容器的强制权限沙箱。服务只在
internal网络和127.0.0.1提供访问，无公网端口、宿主根或/proc挂载。临时凭据文件
位于tmpfs，但容器环境同时存在Docker元数据直至删除；不打印或上传，测试结束
删除本次容器、网络、tmpfs和记录，再由GitHub销毁runner。强杀可能跳过trap，
runner销毁是最后边界。仅上传无凭据UI截图，保留三天。

这不涉及用户电脑、真实服务/账号、生产部署或长期访问。旧M6批准不能复用。
新guard为 `SPRINGBOK_ALLOW_M10_TEST`，仅防误触，不构成认证或用户许可。
提交这份代码也不等于批准运行。

最终工作流仍为默认false的显式手动确认、main限制、reviewed SHA匹配与checkout
前校验，无PR/push/schedule高权限触发。若工具仍不能dispatch，需另给出本次专用
分支bootstrap及硬编码受审源码SHA供独立review；只有取得本轮明确批准后才能
推送触发，成功后必须移除bootstrap再合并，不授权未来任意PR使用Docker权限。
