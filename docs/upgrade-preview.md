# SV-05：保数据升级与预升级测试

负责人主 AI，子任务 `SV-05-S01`。用户于 2026-10-08 批准实现。

## 验收边界

原服务选择固定版本后执行 `update`，保持资源和配置，业务备份/迁移由 `.sba` 实现。
预升级测试从可信当前版本及一致性数据副本创建独立实例，再执行目标版本迁移与发布，
返回独立测试地址；不把空数据安装、共享可写数据库或切换线上流量当作预升级。
测试后由用户手动升级原实例，使用届时线上最新数据；不把测试数据覆盖回线上。
用户手动删除测试实例时，仅清理本实例独占创建的资源。失败/未知保留记录，不自动重放。

## 实施与兼容

复用现有 ConnectionVault、ConnectedDeployment、DeploymentLocks 和固定 SHA 执行链，
不增加存储服务。SBA 扩展必须由应用显式声明，旧 deploy/update/verify 输入输出保持
兼容；旧读者拒绝不认识的新动作。源版本、源任务和资源清单绑定到确认及可信回执。
平台不猜测 SQL、文件格式、邮件/支付隔离或反向迁移。未声明能力、源版本未知、任务
仍在执行或结果未知时不得假装可安全操作。应用仓库属于受审阅可信代码，不把账户级
凭据称作细粒度资源沙箱。

### 应用接入合同

`manifest.json.schemaVersion: 3` 显式声明原 `deploy/update/verify` 与新增 `preview`、
`destroy-preview` 五个动作及各自超时；部署声明须为自动资源版本 v2。v2 应用的原
输入和输出保持可用，不自动声称其已有备份或预升级能力。未知来源的 imported 实例
继续不可升级／预升级，不凭导入声明版本推导线上版本。

`preview` 请求携带目标配置与 `context.source` 的源配置、固定 SHA、源任务、源回执
摘要和资源清单。目标环境由平台生成独立 `test-*`，可写目标必须由实例模板派生。
平台先持久记录资源创建意图，创建独立 D1/KV/R2，再交给固定版本应用入口完成一致性
快照复制、迁移和发布。应用须隔离邮件、支付、回调、定时任务等副作用；平台不替代
应用的一致性策略。返回成功或已部署待验证时，必须提供完整资源创建回执、绑定测试
地址、快照摘要／时间与 `snapshot-copied`、`migration-verified`、`source-unchanged`、
`side-effects-isolated` 全部通过的检查。它们是可信应用证据，不是平台独立数据库审计。

正式 `update` 保持原资源、目标和配置，由所选版本对执行时的当前生产数据做备份和
迁移；v3 成功回执必须包含 `backup-created` 与 `data-preserved`。测试副本不会回写
生产，也没有自动晋级。当前目标适配仍限定 Cloudflare Workers 和声明的 D1/KV/R2，
不新增容器执行器或云厂商。

`destroy-preview` 只读取该测试实例当前成功任务，固定其原代码 SHA、清理清单及回执
摘要；不携带生产源配置。清理必须由应用处理自己创建的 Worker／域名与数据资源，
不能按名称前缀批量删除。全部资源 `removed/absent` 才显示“已删除”；部分失败和
unknown 保留记录、占用和错误，不能重放或自动换任务重试。当前没有失败预升级的
人工恢复／部分资源清理入口，也不释放历史身份供其他实例复用；这些不冒充已实现。

### 合成验收入口

- `tests/sba-preview.test.mjs`：新旧合同及原生 Windows PowerShell。实际复制非空数据、
  仅迁移测试副本，随后加入新生产记录再升级，核对备份与全部生产记录，最后只删除
  测试副本；全部文件位于一次性 `linshi` 子目录，没有真实云调用。
- `tests/cloud/upgrade-preview.test.mjs`：真实 workerd/SQLite、源任务 fencing、双击、
  重启、资源 ID 复用拒绝、unknown 和清理历史保留；供应商和应用回执为合成数据。
- `tests/browser/upgrade-preview.mjs`：真实 Chrome/workerd 的选择版本、预升级审阅、
  独立地址、正式升级、清理确认与取消、双击、焦点和 1440/390/320px 流程。
- 旧服务、导入、新建、四页 Neuro 与邻近 SBA 回归继续运行；上述三项已进入 CI。

## 本轮停止条件

### 线上执行器发布

`SBA_CONNECTED_EXECUTOR_SHA` 将新 connected 部署草稿固定到已验证的执行器 SHA，
对应 `sba-executor-<SHA>` 必须先建立不可更新／删除的标签保护。配置变化使旧草稿摘要失效，
已提交任务仍使用自己持久保存的策略与 OIDC 绑定。旧 `SBA_POLICY` 不改写，避免发布新
执行器改变历史任务身份或回执。此配置只选择代码版本，不授予执行许可，不触发应用部署。

完成协议和新旧混用回归、源/目标隔离、重复提交/重启/并发、清理归属与部分失败检查；
跑真实产品 workerd/Chrome 合成流程及四页 Neuro 回归，保留 UTF-8 证据与截图。
每个交付阶段记录源码版本和未验证项，正常 scoped 提交推送、精确 PR 审阅及 main
复核。真实应用适配、生产数据升级与云端清理均不由合成通过替代，也不在本轮执行。
