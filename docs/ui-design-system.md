# SpringBok UI 设计规范

版本：UI-01 · 2026-10-07。适用范围：`public/cloud-admin/` 的正式云管理界面。
本文件是 Neuro 设计方案在 SpringBok 中的落地规则，不另建竞争主题。

四页静态壳层保持相同导航顺序；更新时一起修改，并运行四页浏览器检查。静态导航

`tokens.css` 和 `shell.js` 仍经原 Access 验签和 no-store，不能变成匿名公共入口。

## 2. 颜色语义

| 令牌 | 色值 | 使用场景 |
| --- | --- | --- |
| `--neuro-signal-yellow` | `#d9ff38` | 当前导航、键盘焦点、当前步骤唯一主操作、待注意 |
| `--neuro-signal-green` | `#22c55e` | 品牌、服务端已证实的成功或完成 |
| `--neuro-info-blue` | `#06b6d4` | 链接、技术信息、只读状态 |
| `--neuro-danger-red` | `#f43f5e` | 错误、风险与停用确认 |
| `--neuro-bg` | `#06080d` | 应用主背景 |
| `--neuro-surface` | `#090c11` | 顶栏、连续内容板 |
| `--neuro-panel` | `#0e1218` | 分组、弹窗 |
| `--neuro-rail` | `#070a0f` | 侧栏 |
| `--neuro-control` / `--neuro-control-hover` | `#111720` / `#18222c` | 控件常态及悬浮 |
| `--neuro-text` / `--neuro-text-muted` | `#f7f8ef` / `#929a9f` | 正文及次级文本 |
| `--neuro-line` | `rgba(255, 255, 255, 0.12)` | 分隔线 |
| `--neuro-focus-surface` / `--neuro-focus-ink` / `--neuro-focus-muted` | `#f3f5f1` / `#20252b` / `#656b72` | 将来需要的白色重点阅读面，必须成组使用 |

黄、绿各只有一个主色；hover/pressed/soft/border 从令牌用 color-mix 派生，不新增
相似黄色或绿色。黑灰承担绝大部分面积，避免多个黄色按钮争抢。白色焦点面只在
确有重点阅读需要时使用，本次不为“凑规范”把表单改成白底。

连接验证通过只表示只读验证通过；绿色必须保留这段限定文字，不能称部署就绪。
Actions success 不等于应用成功。未知、停用、失败不能画成绿色。连接/资源/新部署通知通过显式
`data-tone=info|success|warning|error` 映射颜色，不从错误文本关键词猜语义。
品牌绿色标记不是在线指示器，不能据它声称云资源可用。

## 3. 布局与密度

- 桌面：左 rail + 56px 顶栏 + 独立滚动主区。侧栏 216px，窄桌面 184px。
  Gateway/Crow 的 186px 桌面侧栏是参考而非机械复制：Web 没有原生窗口控制，按
  SpringBok 的中文导航及浏览器缩放调整；不伪造最小化、最大化和窗口关闭按钮。
- 主区 padding 30px/32px；宽屏内容最大 1380px。页面标题 28px、分组标题 18px、
  正文 15px，说明 12–13px；表单内最多两列，密钥、JSON 及长 ID 使用等宽字体。
- 导航固定为历史部署、新建部署、云资源、底部连接设置。当前项有黄色软底、边线、
  2px 内侧信号线和 `aria-current=page`，不是只改变图标颜色。
- 720px 及以下：导航转为四项顶部网格、隐藏冗余上下文栏、单列表单，允许页面滚动。
  保留文字标签，不用用户猜图标；320px 也不得产生横向页面滚动。
- 连接、资源采用高密度行，不构造等权卡片墙。列表最大高 560px；JSON 回执最大高
  460px 并独立滚动，长账号/资源/错误可断行，避免撑开应用壳层。
- 结构装饰限制在品牌符号、标题绿色三角、步骤编号与细边框。不引入渐变光球、玻璃
  面板、大圆角、持续动画、巨大空白或与业务无关的虚构仪表盘。

## 4. 页面任务与主操作

| 页面 | 主要任务 | 视觉主操作 | 必须保留的信息 |
| --- | --- | --- | --- |
| 连接设置 | 添加/验证/停用凭据引用 | 验证并保存 | 只读权限边界、加密不回显、停用影响、真实状态和错误 |
| 云资源 | 添加品牌密钥、按账户查看资源 | 页面“添加资源”；弹窗“验证密钥并添加” | 账号归属、只读权限、分页/部分失败、显式部署选用与自动目录的区别 |
| 新建部署 | 选定版本和资源、审阅后执行 | 读取声明 → 审阅计划 → 确认部署，随当前阶段切换 | 精确 SHA、首次部署风险、公开配置不可填秘密、不可自动重试 |
| 历史部署 | 查看已有固定任务及回执 | 默认以次级读取按钮为主，确认弹窗才强调执行 | 历史联调边界、原 unknown、许可与真实结果 |

刷新、清空、取消、重新验证和查看结果都是次级按钮。停用用红色次级样式和应用内
dialog 二次确认；该停用弹窗取消优先获得焦点。不要用“更简洁”为理由删除风险、权限或
结果信息；长背景说明可收在 details 中，关键执行警告必须持续可见。

## 5. 状态、键盘与可访问性

云资源采用“账户目录 + 品牌添加弹窗”模式（UI-03，替代 UI-02 的类型优先入口）：
页面右上角仅放添加资源，不放刷新。弹窗内容首行是 Cloudflare/GitHub 品牌 SVG 与文字，
使用原生 radio 表达单选；下方填写密钥及账户备注，验证保存后自动按账户展示可读取资源。
不能让用户先选 D1/KV/R2 再找凭据。账户标题显示品牌和真实账号名，资源类型为下级列表。
目录自动读取，部署选用显式触发，不能通过浏览页面隐式部署或改掉已审阅绑定。
关闭/Escape 恢复到添加按钮，并清空密钥；提交时立即清空输入，失败不自动重提。
错误在弹窗内可见，各类型读取失败与空列表区分。详见 [品牌资源目录契约](brand-cloud-resources.md)。

- 默认、hover、focus、disabled 均可读；禁用控件用暗表面、虚线边框及原生 disabled，
  不只降低透明度，不允许禁用的黄色按钮看起来仍可执行。
- 焦点为至少 2px 黄色 outline；提供“跳到主要内容”链接，键盘顺序遵循 DOM。
- 弹窗使用现有原生 dialog 与控制器的 Escape/取消逻辑；连接停用弹窗进入时聚焦
  取消，关闭时恢复触发点。历史一次性加入弹窗保留原生首控件“保存加入材料”焦点，
  不称已统一改为取消优先；新增风险确认弹窗应取消优先。弹窗出现时锁定背景主区
  滚动；不得更改提交/停用语义来实现动画。
- live region 保留 `role=status` 与 `aria-live=polite`；错误持续留在页面，不靠 toast
  瞬时消失。状态必须有文字，图标为 aria-hidden 装饰，不重复朗读。
- 导航、渲染和改配色不能发送写请求；不能用 localStorage/sessionStorage 保存凭据
  或部署数据。本次也不增加偏好存储，不实现不存在的主题/语言切换。
- 交互过渡 140ms；`prefers-reduced-motion` 下关闭非必要过渡和滚动动画。

## 6. 后续设计流程与验收

1. 先读本规范和 Neuro 唯一源，再读真实页面/控制器/测试；不要仅照截图猜业务。
2. 优先复用 token、控件及布局；新增组件需要说明真实任务，不引入第二套主题 API。
3. 保持 ID、事件、权限和不可重放边界；新增资源必须加入现有鉴权 allowlist 并补拒绝测试。
4. 跑 `node tests/browser/neuro-ui.mjs`：四个真实页面 + workerd、1440/960/720/390/320
   宽度、令牌、焦点、Escape/恢复、滚动、错误/禁用及审阅截图。设置测试环境 TEMP/TMP
   和 `UI_EVIDENCE_DIR` 到 linshi，浏览器供应商与 Access 均为合成数据。
5. 跑连接、资源、声明、执行、旧 SBA 浏览器流程与匹配 Node/workerd 回归，检查实际
   截图，不以 CSS 合法或参考网页截图代替产品验收。
6. 记录精确 commit/PR/main、安全检查、发布和人工验收边界。只有真实登录的线上
   用户操作才可称线上 UI 验收；本地合成截图不可冒称用户线上数据。

本次不改 `public/demo` 等历史本地样例，避免把旧 fixture 验证重新解释为正式产品。
它们不是线上 cloud-admin 的设计入口。现有 NAccount、DO 数据和任务回执也不在视觉
迁移范围内。后续如增加浅色/跟随系统需独立设计、实现和验收，不先摆空开关。
