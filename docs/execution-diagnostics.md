# M8：只读执行证据说明

临时测试控制台的每个有执行记录的服务卡新增“查看执行证据与阻断原因”。
它展示最近执行或未确认配置准备的原因、下一步、请求 ID、确切 Update ID、
目标及观测时间。不接受调用者指定任意资源、URL、执行结果或替代证据。

## 查看与核对不同

查看只读取已持久记录绑定的证据，不写 journal，不修改配置，不部署、重启、
恢复或清空记录，不授予验收。即使当前观测符合成功条件，也只提示使用原有
“刷新执行证据”重新验证并持久记录；不会提前把服务标为成功或允许晋级。

- Queued/InProgress：显示排队或执行中，建议等待后再查看
- Update ID、操作或目标不一致：证据不匹配，保持阻断
- Update 完成且失败：提示重新核对并记录失败
- 完整配置或目标身份不一致、容器镜像错误：明确显示未确认，不自动修复
- OOM、暂停、健康 starting/unhealthy、证据不足：分别说明，不冒充已记录失败
- 非 OOM/非暂停的固定镜像明确退出 1：提示原流程重新验证并记录样例失败
- 配置准备未知或 Deploy 回执未知：不猜 ID，不发任何后端读取或执行，保持阻断
- 已记录成功或失败：明确标为历史结果，不声称查询了当前容器健康
- 读取错误或超时：只报告无法读取，不据此推断执行结果

结果是一次有时间标记的观测，不保证以后仍相同。记录 revision 改变后界面隐藏
旧说明。独占操作锁防止本控制器边读边写；它不保证对其他 Komodo 写入者的
配置所有权，也不消除外部配置竞态。当前没有安全的未知结果人工重绑定功能，
因此界面不会提供“强制解锁”或建议删除日志来继续。

## 数据与验证边界

后端仅返回固定白名单分类和来自本地固定计划的 ID，不返回原始日志、完整配置、
异常文本或连接凭据。HTTP 仍只监听 loopback，要求精确 Host/Origin、内存 CSRF
及当前 revision；这些机制不构成生产身份认证。

本轮沿用普通单元/假后端 HTTP/真实 Chrome 回归，不新增真实 Komodo 测试，
不申请 Docker 管理权限或登录凭据。浏览器截图明确标注假后端；诊断分类实际
覆盖不等于已在真实服务重现所有故障。原 M6 证据仍只证明其历史源码，CI继续
核验精确历史提交、树与20项哈希，后续变更列于
[test-console-evolution.json](test-console-evolution.json)。

```sh
node --test tests/*.test.mjs scripts/ci/security-baseline.test.mjs
# 已安装 Chrome 和锁定的测试依赖时：
node tests/browser/execution-review.mjs
```

后续优先补接入前的固定资源配置校验及可读差异，再讨论真实环境的人工核对
权限与恢复方案；不应通过放宽 unknown 阻断来提升表面可用性。
