# M3：本地演示控制台

## 打开界面

目前仅支持 Linux、Node.js 22+。Windows/macOS 的目录 fsync 和符号链接保护
尚未验证，启动前会明确拒绝，不先写入记录或降低持久性保证。
在此仓库根目录运行：

```sh
node scripts/demo.mjs
```

浏览器打开终端打印的 `http://127.0.0.1:3210`。必须使用这个精确地址，
不是 `localhost`。Ctrl+C 正常退出。Linux 桌面需已有中文字体（如 Noto CJK）；
缺失时请使用发行版官方字体包，应用不会自行安装。运行界面无需 npm 安装、Docker、Komodo
或任何账号/密钥。服务只监听 IPv4 loopback，不支持公网暴露或反向代理。

页面一直显示 **DEMO · 未连接真实服务器**。Gateway、论坛、游戏、账号只是
四个独立的发布流程卡片，不是四个业务系统的实现。

1. 点击“模拟测试通过”；也可先点“模拟测试失败”观察阻断
2. 查看候选制品和配置摘要，勾选“仅模拟验收，不是生产授权”
3. 点击“确认模拟验收”，然后“模拟晋级”
4. 选择 v2 候选并重复测试、验收、晋级，再“模拟回滚”到已成功的 v1
5. 正常停止后重新启动，成功模拟版本与历史仍在；尚未使用的模拟验收被撤销

测试/晋级/回滚结果均来自用户明确选择的合成结果。没有运行真实任务、后台
部署或自动审批。首次模拟晋级失败且没有已成功版本时，界面保留失败状态，
不能凭空回滚或绕过该状态；本里程碑不实现任意清空/重置按钮。

## HTTP 边界

- 固定资源白名单、固定服务与动作；没有文件浏览、URL、命令或真实 adapter 接口
- 精确 Host 校验；有 Origin 的请求只接受自身；拒绝跨站 Fetch Metadata
- 写入必须同源 Origin、JSON、当前启动期内存 CSRF token；请求上限 2 KiB
- 不设置 CORS 或持久 cookie；token 不落盘、不写日志；重启后旧页面先刷新
- CSP 禁止内联脚本、框架嵌入、外部连接；响应 no-store / nosniff / no-referrer
- 全局 revision 防止旧页面、双击和多标签页重复提交；失败不会自动重试写操作

CSRF token 不是用户登录或访问凭据。任何能控制这台机器的进程都可能操作
演示；浏览器自动化也能点击模拟验收。服务端固定的 `demo-operator` 仅用于
演示契约，绝不能当作生产人工身份。不要将此监听转发到公共网络。

## 持久化、恢复与损坏处理

只使用当前仓库下 `.springbok-demo/`，已加入 gitignore。记录中没有 token 或
真实凭据。固定 `ledger.json` 保存严格版本化的演示动作，最多 1000 条/1 MiB。
每次操作先在新的契约实例中完整回放验证，再写唯一临时文件、fsync、原子
rename 和目录 fsync；全部成功后才更新内存/返回成功。写入失败后该进程
停止提供可用状态或接受写操作。若失败发生在 rename 之后，磁盘可能已经
持久化该操作，但客户端仍不会收到成功；重启检查历史再决定下一步，勿盲重试。

启动时发现尚未消费的模拟审批，会追加 `restart` 事件，列出对应审批记录号。
回放只跳过这些审批，回到待模拟验收；历史记录不删、已消费审批与成功版本
不改、不伪造新的测试结果。重复启动不会再次撤销同一审批。M1/M2 的核心
契约和真实集成执行文件不修改，原集成证据 hash 校验仍有效。

损坏 JSON、不支持版本、非法历史/恢复事件、符号链接、已有独占锁都拒绝
启动，不自动修复、清空或覆盖。原始记录保留。专用目录和文件检查旨在
防止误用，不防御能同时改写本地目录的恶意进程。

### 崩溃后的 owner.lock

正常 Ctrl+C 会释放当前进程自己的 `owner.lock`。断电、强制终止可能留下锁，
下次启动会拒绝，而不是猜测锁已过期。处理步骤：

1. 保留 `.springbok-demo` 的完整副本，查看 `owner.lock` 中的 PID
2. 用系统任务管理器确认原 SpringBok Node 进程确实已退出，同时确认没有
   另一个演示实例在运行。PID 可能被复用，不能只凭 PID 不存在/存在下结论
3. 只有确认无人使用此专用目录后，由你手动移走 `owner.lock` 留作备份，再启动
4. 如果 ledger 校验失败，保留记录并排查；不要自动删数据来“修好”

程序没有删锁、杀进程或迁移历史的远程接口。容量已满时保留记录，使用另一个
干净仓库副本体验新演示；不要把用户已有目录传入测试程序。

## 验证

```sh
node --test tests/*.test.mjs scripts/ci/security-baseline.test.mjs
```

普通 GitHub `Demo Browser` job 使用 runner 已有 Chrome 与锁定的 Playwright
测试依赖，并从官方 Ubuntu 包下载 Noto CJK 字体，仅解包到临时 runner 用户
字体目录（无 sudo），确保中文截图可读。覆盖真实 DOM 操作、键盘验收、失败/重试、v1→v2→回滚、刷新、
重启撤销审批、旧 token/多标签页以及移动宽度。仅测试依赖是 Apache-2.0
Playwright；不进入应用运行时、不替项目决定许可证。不安装系统浏览器、
不使用 Docker socket、无权限提升、无服务公网端口。产物只有演示页面截图，
保留三天，不上传 ledger/token/浏览器 profile。
[官方 Chrome channel 文档](https://playwright.dev/docs/browsers#google-chrome--microsoft-edge)。

云端交互浏览器可能禁止访问 loopback；那不代表截图验证已通过。以准确
PR/main 的 `Demo Browser` 实际结果为准，截图来自该次浏览器执行。
