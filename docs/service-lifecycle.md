# 服务生命周期与控制面操作

本页承载平台实现与操作边界；文件、字段、检查名以[部署声明](../ai-docs/deployment.md)、
[应用生命周期](../ai-docs/lifecycle.md)和[接入流程](../ai-docs/integration.md)为唯一参考。
源码入口为 `cloud/deployment-api.mjs`，本页不代表线上启用或生产操作许可。

## 服务发现与实例

浏览、切换和预览不部署；确认后才准备资源并提交一次任务。服务列表保留最近确认版本、
当前目标版本及原始回执，失败不抹掉前版本。统计中的绑定资源用量不等于实例独占用量。

遍历每个有效 GitHub 连接的所有仓库分页，以大小写无关的仓库名去重；账户级凭据
直接只读访问选定仓库，不批量派生连接。默认分支先解析为完整 commit，再核 Git tree
中的根 `.sba` 目录和普通 manifest/deployment blob。不存在目录不展示为服务；无效
声明、权限失败和分页未完成保持可见且不得部署。版本来源为默认分支与分页 tags，
选择后始终按返回的完整 SHA 读取和执行，不向执行器传浮动 tag/branch。

## 实例与增量兼容

- 复用 ConnectionVault、ConnectedDeployment 和 DeploymentLocks，不增加 DO 绑定。
- 原 `connection_deployments` 索引记录增量保存服务摘要；首次 task ID 即 instance ID。
  一次更新有新的 task ID，携带 instance ID、前一 task ID、前版本和绑定回执摘要。
- 旧记录缺摘要时从不可变 bootstrap 按 owner 核对读取，不清库、不重写密文/AAD。
  旧连接/资源/部署 API 继续可用；已有 fixture/service catalog ID 不改名、不复用。
- `/history` 保留旧固定部署、节点与历史记录界面，但普通导航不显示它；旧固定 SBA
  不自动纳入可更新实例，也不绕过其保护身份。只有明确记录的自助实例可在此更新。
- 回退控制面不会丢失新记录。旧代码不认识 update request 时失败关闭；已有目标键
  仍属于首次 task，新旧首次部署都不能抢占它。需要完成在途更新时应恢复新控制面，
  不能靠旧版本重新 dispatch。无破坏性收缩或自动反向数据迁移。

## 版本更新不变式

更新复用 SBA v2 的 `update`，而不是再次 `deploy`。manifest application ID、仓库、
账户、环境、资源实际 ID/名称、目标和完整公开配置保持一致。声明不兼容时失败关闭，
平台不推断业务配置迁移。业务数据迁移由新 SHA 的 `.sba` 实现，平台不写业务 SQL。
现有契约仅允许严格更高的 `x.y.z` 版本及不同 SHA；不提供未验证的数据降级/回滚。

前任务必须有核验回执且为 `succeeded` 或 `deployed-unverified`。后者仍显示“已部署，
待验证”，不能改成业务成功。进行中、失败、unknown、准备未确认都不能发起下一次
更新。服务行保留最近确认版本，并另显示更新目标版本与结果；失败不能抹掉前版本。
Vault 在同一事务中比较实例最新 task；账户锁在同一事务中比较前 claim、owner、
原始资源键与串行 lane。保留所有旧 claim；结果未知不释放锁。重复提交同一 task
只读取已有状态；许可/source/receipt 仍走既有 OIDC、digest 和一次性执行链。

## 自动资源准备

字段与账号槽见共享部署声明；v1 使用已有资源，v2 按声明准备资源。

1. 审阅批准绑定预览摘要；服务端重读源码与连接后逐字比较计划。
2. Vault 原子保存准备意图和资源容量预留，再按排序后的账户列表取得各自占用。
   后续账户冲突时不创建任何资源；已持有的占用保留，不能用新任务绕过。
3. 每个 POST 前持久保存 `creating`，调用 Cloudflare D1/KV/R2 固定创建端点，
   不重试、不跟随重定向，限制超时和响应大小，校验返回名称与 ID。
4. 每次确定成功立即保存结果；全部完成后原子登记资源，生成最终公开配置。
   名称和返回 ID 均绑定到账户占用，之后才初始化任务和派发 GitHub 执行器。
5. 重复提交只读取状态；崩溃、响应未知或部分成功不再次取得创建权。
   已知创建资源仍保留在准备记录中；不得自动删除、回滚或重新创建。
6. Runner 一次性许可只取得 manifest 明确声明的来源凭据，未使用连接不传递。
   沿用已批准 in-flight 任务的既有凭据语义，后续停用连接不是取消该任务的回执。
7. 更新从前一可信任务继承配置与资源，验证身份/目标/配置不变，不再创建资源。
   原 v1、导入记录和原 NAccount unknown 回执不被重写。

扩展复用原 SQLite Durable Object 表，不清空或迁移历史数据。旧版控制器回退时
仍可看到索引和占用，新 v2 声明不受旧版支持；不能用回退作为准备未知任务的恢复方法。

unknown 保留资源容量与占用。未开始准备的显式恢复条件见共享生命周期，不能据此重放已创建或未知资源。

## 导入现有服务

服务页右上角分别为“部署服务”和“导入服务”。复用同一服务目录、不可变声明版本
读取与稳定弹窗。导入选择服务、声明版本、账户和现有 Worker；D1/KV/R2 由实际
绑定读取，在预览中只读显示。确认仅登记，不 dispatch、不创建资源、不执行迁移、
不修改应用代码/域名/配置、不读取业务数据或秘密值。

当前兼容 v1 `cloudflare-workers` 声明，从 `targets` 的 Worker 路径取得组件。
单账户内绑定必须真实可读，缺失必需资源类型、部分权限或读取不确定时拒绝登记。
固定 SHA 是所用声明的来源，不是实际部署版本。没有可信部署证明时显示“版本未知”，
`canUpdate=false`；不能把 GitHub 最新声明版本冒充线上版本或开启版本更新。

## API 与持久边界

- 普通用户：`POST /api/admin/deployments/import-preview`、`import-submit`。
  复用 Access owner、Origin/CSRF 和 ConnectionVault 的有效连接/密钥隔离。
- 预览不写实例或占用；2 分钟确认签名绑定输入、可信读取摘要和到期时间。
  提交重新读取固定声明及供应商元数据，摘要变化必须重新预览，不接受客户端改写。
- 只请求 Cloudflare 官方 API：Worker settings、Worker domains、D1 元数据、
  KV namespace 分页、R2 bucket 元数据。采用有界 JSON/超时/禁止重定向；不请求
  应用返回的 URL，不读取 KV values、D1 rows、R2 objects、secret values。
- 实例 ID 绑定 owner、账户与排序后的 Worker 集合。独立 `service_imports` 表与
  version 1 标记保留导入快照；同 ID 重试返回原记录，不隐式刷新或覆盖原来源。
- 账户 DO 原子登记资源占用，再保存 owner 索引。中断后保留占用，由同一身份重试
  补全；不因存储超时释放不确定占用。跨 owner/服务的资源争用拒绝，导入不占执行 lane。
- 导入键同时登记到旧 `deployment_keys`，使旧控制面回退后仍拒绝抢占。原连接密文、
  资源、部署索引、任务和回执均不重写；不增加 DO 绑定或破坏性迁移。回退隐藏新实例，
  不删除记录；恢复新控制面可继续读取。没有自动清理和解锁接口。

### 固定 policy 任务的兼容导入

专用 `POST /api/admin/sba/import-preview` / `import-submit` 只接受原 task ID 与
声明 SHA，账户/目标/资源从已消费 permit 且有结果的原任务取得。再次核对实际
Worker/资源和原配置，保存 `legacy-task` 来源，原 `unknown`/错误/历史保持原样。

机器身份仍不能访问普通管理 API 或静态页面。除原有有效授权外，需临时非秘密变量
`SBA_IMPORT_APPROVAL`，精确包含 `taskId`、`definitionSha`、`jobDigest`、`issuedAt`、
`expiresAt`。摘要覆盖原 request/status/runId/result，时限最多 15 分钟且不超过
原机器授权期限；过期、缺失、变更均拒绝。不能通过该入口自选 owner/账户/资源/密钥。
完成后撤下该临时批准，保留原 Access 配置和授权期限。它不是重新部署授权。

## 隔离预升级与修复

原服务选择固定版本后执行 `update`，保持资源和配置，业务备份/迁移由 `.sba` 实现。
预升级测试从可信当前版本及一致性数据副本创建独立实例，再执行目标版本迁移与发布，
返回独立测试地址；不把空数据安装、共享可写数据库或切换线上流量当作预升级。
测试后由用户手动升级原实例，使用届时线上最新数据；不把测试数据覆盖回线上。
用户手动删除测试实例时，仅清理本实例独占创建的资源。失败/未知保留记录，不自动重放。

- 原失败任务和 GitHub run/permit/result 保持不可变，不 rerun、不覆盖结果、不伪造成功。
- 新任务固定父任务、原 request/result 摘要、应用修复声明、源 SHA、原资源与配置；预览和
  提交均重新核对父任务仍是实例当前头，且 GitHub 原 run 已终止并取得可验证业务回执。
- 应用声明允许修复的错误码、操作标识及所需秘密。平台不理解 NAccount 表结构或自动推断
  迁移；不把 verify 升级为写操作，不把管理员 bootstrap 密码传入后台修复。
- 账户 lane 原子移交给新修复任务，不先释放再竞争；一次预留、一次 dispatch、一次 permit。
  丢回复/重启/并发不得隐式重放。旧资源所有权仍属于同实例，其他实例不能抢占。
- 普通 repair 与副本 repair 成功需证明修复完成、数据保持、非修复资源未改变及服务配置就绪。
  清理 repair 按共享生命周期验证清理及 `repair-completed`，不要求虚假的数据保持或服务就绪。
  新成功是新任务
  对当前状态的证明，不追溯更改旧 unknown。失败继续占用，不自动清理或重试。

预升级清理固定原 SHA、原回执和精确清单，不能按名称前缀批量删除。部分清理的显式
`resumeCleanup: true` 已有实现，但只适用于共享生命周期列明的受限修复，不是任意 unknown
重试。普通删除的只读核对是另一条接口，不与应用清理恢复混用。

## 普通删除与退役登记

支持范围、R2 有界对象清理、邮件 DNS 和 suite 限制见共享部署声明，不再保留旧的
“R2 尚未实现”结论。预升级副本走应用清理合同；suite 的受限退役登记不等于破坏性删除。

- 控制面已有资源供应接口负责固定 Cloudflare API 的删除，不要求旧应用新增执行动作，
  不改写旧 GitHub SHA、执行器授权或应用结果；这是平台资源管理，不是应用迁移。
- 管理请求要求真人 owner、Origin、CSRF。两分钟确认绑定 operationId 与完整计划摘要；
  提交重新检查源实例最新任务、连接 revision、资源身份与供应商元数据。
- 当前 Worker settings、Pages 当前配置与公开返回绑定信息的保留部署发现共享 D1/KV
  即拒绝。Pages Functions 未返回某待删类型绑定时，计划明确列出账户、项目、部署 ID
  和未知类型；默认不勾选，只有 owner 明确接受未核验引用可能影响其他服务的风险后
  才能提交。风险清单与接受风险的确认范围绑定签名，提交重新核对，不把未知当空绑定。
  分页未完整读取、权限不足、额外未登记数据绑定或资源漂移均失败关闭。读取有界。
- 检查不等于整个账户的任意外部消费者审计；历史 Worker 环境、其他账户/供应商或
  应用通过 HTTP/API 使用资源的依赖不能由当前接口完整证明。Cloudflare 的删除不是
  compare-and-delete，外部管理员并发改名/重建仍需避免；不使用 `force=true`。
- owner SQLite DO 在任何云写前保存意图；逐账户占用原资源归属和执行 lane，
  并阻止同实例升级/预升级。按域名、Worker、数据存储顺序执行，逐项先记 deleting。
- 2xx 空正文合法，仍必须按[各资源的不存在证明合同](../ai-docs/deployment.md)独立读回 absent；
  D1 核对原 immutable UUID 的精确不存在响应，不以列表缺项代替。全部再次读回后释放精确归属，
  清理已删除资源的目录登记。同名新建使用新实例 ID 与新资源 ID，历史回执保留。
- 删除过的导入身份保留 tombstone，不静默重新登记成活实例；需要新的身份/明确后续
  代次流程，不能复用旧 claim 伪造资源占用。

云请求响应丢失、部分删除、锁或持久化故障保留 `delete-unknown` 与逐项进度，
不自动重放 DELETE，不移除历史条目伪装成功。重复 operationId 只读原记录。

`delete-reconcile` 只读核对原清单；全部资源确认 absent 后才能收尾，不重发 DELETE。
中断遗留 deleting 超过两分钟显示删除未确认；重复请求不伪造成功，也不释放未知占用。

服务面板在读到权威 `deleted` 状态后不再展示该实例，也不为其读取资源用量；此规则同样
适用于已完成清理的预升级副本。删除中、删除未确认、失败或读取失败仍显示。
这是当前列表的展示规则，不删除后台索引、任务历史、删除回执或 tombstone；原精确 ID
的状态查询仍可核对历史，不重新执行删除。

## 管理员资料

云资源的“添加资源”支持 Gmail 管理员资料：邮箱和默认管理员密码。这里只登记应用登录资料，
不申请 Google OAuth、不读取邮箱，也不把邮箱标为已验证。密码至少12字符且包含大小写、数字、
符号，UTF-8最多72字节；真实默认值只保存在 owner 隔离的 AES-GCM vault，不在代码中预置。

支持初始化的自动部署声明可添加 `administrator: {emailPath, secret}`。
部署表单选择管理员邮箱（只有一个时默认选中），默认使用保存的密码；选择“本次密码”可覆盖。
预览只显示邮箱和密码来源，不显示值。返回修改可明确切回默认密码。

临时覆盖有效15分钟，创建新资料时回收已过期覆盖；被确认任务另有私有密文副本，不受临时
引用过期影响。签名计划只有不可猜测引用和公开邮箱；一次性 OIDC permit 向固定SHA应用传秘密。
列表、配置、GitHub dispatch、日志、回执均不得带密码或密码摘要。更新及预升级只传不适用标记，
不解密原管理员密码，不重设账号或授予旧账号权限。

## 域名登记

Cloudflare 云资源目录增加“域名”，通过账户限定的 active Zone 只读列表发现、分页并登记。
共享 Zone 不是服务拥有的数据资源，不自动创建，也不随服务删除。

自动新建表单按应用声明的每个 domain target 提供已登记域名和单层子域名选择。
选择域名后，后端核对登记与连接 revision、账户归属、Zone active 状态和名称，
并检查精确 hostname 的 DNS：允许同名 MX/TXT，拒绝其他冲突记录；公开配置中的 HTTPS origin 由后端生成。
计划与提交都重新读取，最终 URL 进入签名计划的 configuration 和 targets。
登记引用保留在签名草稿中，不作为可删除资源加入 plan.resources。

有默认模板时未选域名继续使用模板；没有模板的域名字段可手动输入 URL。
选择 Zone 时禁用对应手动输入，取消选择后恢复，不能把两种来源同时提交。
既有 API 显式 URL 配置继续保留：它不具有登记 Zone 路径的归属与 DNS 预检保证，
仍受目标合同、账户占用和应用发布预检约束。不能声称所有显式 URL 都已核验 Zone。

同实例升级保持原 URL；不提供域名迁移。应用负责实际 DNS 与证书发布，平台不另造应用部署入口。
provider 预检与后续发布不是原子 create-only；外部管理员并发修改仍可能产生竞态。
连接验证不等于已证明 Zone/DNS/Workers 的发布权限；真实绑定成功需单独验收。

## 开关与验证

停用连接不是取消已批准任务；紧急阻止后续 connected 许可需关闭
`ENABLE_CONNECTED_DEPLOYMENTS`，不能把开关当作撤销已交付秘密或回滚外部副作用。
旧任务和历史读取保留。执行器 pin 与兼容恢复见[控制链](sba-cloud-control.md)。

对应验证为 `tests/cloud/` 的 service-lifecycle、automatic-deployment、service-import、
upgrade-preview、service-repair、service-deletion 测试及同主题浏览器流程。
合成供应商、workerd 和 UI 回归不代替真实云操作或用户业务验收；历史记录从 Git/PR 查询。
