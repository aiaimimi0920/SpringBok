# M7：执行前核对目标和版本

M6 临时测试控制台现在对“执行真实测试”“晋级测试版本”“回滚已知成功版本”
先显示确认面板，再执行。面板列出服务、操作、临时目标环境、资源名称和 ID、
不可变镜像、发布配置摘要、目标配置摘要与记录 revision。回滚显示契约派生的
已知成功版本，不使用当前候选冒充回滚目标。

这仍是临时测试控制台，不是生产认证。确认计划不代替测试验收，也不证明
操作者是用户或阻止 AI 自行点击。同机进程仍属于已有测试信任边界。

## 操作与过期

- 点击操作只读取固定目录和当前记录，预览不请求 Komodo、不写 journal
- 取消、关闭、Escape 或返回浏览历史均放弃当前面板；再次打开重新取计划
- 确认使用服务器随机内存密钥签名，绑定请求 ID、服务、操作、revision、
  完整计划和两分钟截止时间；凭据和确认签名不写入 journal
- 服务端在原互斥锁内重算计划、验证签名和过期时间，全部通过才允许原有
  preparation intent → 配置写入 → 执行意图 → Deploy 流程
- 另一标签修改记录、重启、签名被更改或过期时拒绝执行。刷新记录后重新打开
- 重复确认不能发送两次；失败不会自动重试。已有 unknown 仍保持阻断

这些检查绑定本地记录和预配置目录，不消除其他 Komodo 写入者造成的配置竞态，
也不是服务端配置 CAS。原有提交前检查与执行后证据核对继续生效。

## 验证与证据边界

本轮不申请或运行新的 Docker 管理权限，也不生成登录凭据。普通测试使用
真实控制器和假后端，浏览器回归使用真实 Chrome，覆盖取消、关闭、Escape、
迟到预览响应、Back/Forward、重新打开、多标签过期、双击、重启和手机宽度。
截图明确标注“假后端、未执行容器”。不能把它们称为新的真实 Komodo 部署证明。
