# SpringBok：给服务接入 AI 的入口

目标：在你维护的服务仓库中实现 SBA 接入，让 SpringBok 能按固定版本、安全确认和可验证回执部署服务。这里是接入规范，不是允许你操作用户云账号的授权。

## 先理解职责

SpringBok 是 Cloudflare Workers 上的部署控制平台。当前代码提供：连接 GitHub 与 Cloudflare、选择服务固定提交、配置资源和域名、预览、确认、执行、收集回执，以及同实例更新、隔离预升级和显式修复。NAccount 已有真实部署、后台修复与管理员登录验收；不能据此声称隔离预升级或任意生产数据迁移已通过真实验收。平台持久任务使用 SQLite Durable Object。

应用负责构建、部署、备份、迁移、业务验证与真实失败判断。SpringBok 不会替应用推断数据库结构，不提供任意应用自动适配，也不会把 HTTP 200 或 CI 绿色自动当成业务成功。

外部服务器部署与集中监控属于项目产品路线；不要把 Cloudflare SBA 接入示例解释成任意供应商、任意操作系统都已支持。

## 阅读顺序

1. 阅读 [接入任务](integration.md)，先调查自己的服务，而不是直接复制部署命令。
2. 阅读 [文件结构](files.md)，区分仓库文件、运行时输入和输出。
3. 阅读 [manifest](manifest.md) 与 [deployment](deployment.md)，它们使用不同的 schemaVersion。
4. 实现 [请求、回执与生命周期](lifecycle.md)，尤其是数据保留和 unknown。
5. 按 [本地验证与排错](validation.md) 检查；示例是失败关闭的教学骨架，不是已实现的部署器。

## 给 AI 的硬约束

- 源码校验器是协议事实来源；当前新接入使用 manifest v3、deployment v2，禁止从旧 v2 历史文档猜规则。
- 不把秘密写入 JSON、公开字段、文档、日志、Actions inputs 或 artifact。
- 所有云写、清理、资源创建、管理员初始化都必须有与具体操作相符的授权；文档不授予授权。
- unknown 先核对，不自动重放、不伪造成功、不通过删数据消除问题。
- 不声称未实现的 action 可用；v3 必需动作若尚未完成，应在写入前失败关闭，并明确接入未完成。
- 修改协议时同时检查本目录与人类站点 `pages/`。本目录参考页是两种阅读入口共用的事实文本，页面站点不另写一套字段定义。

## 交付给服务维护者

列明新增文件、支持动作、固定来源、验证命令及结果、权限与秘密名称、未验证的云操作和人工验收。运行通过、已推送、已部署、已完成业务验收是四个不同结论。
