# 基线与候选配置的发布差异

在已有配置检查页选择候选JSON，再选择可选基线JSON（顺序也可相反）。每份最多
64KiB，二者均由M12编译器规范化验证。基线与候选必须属于同一project。下载内容
由单份user-configuration-review变为deployment-change-review，绑定两份manifestDigest
以及按固定服务/字段顺序产生的差异。相同配置换序不会制造变更；任意一份配置改变
都会改变相应摘要和reviewDigest。下载仍必须手动点击。

这里的基线仅是**用户提供的历史配置**，不是从服务器查询的当前配置，也不是部署
成功、测试验收或回滚证据。没有基线时不会猜测当前状态；没有变化也不代表允许发布。
executionReady、readiness、executable始终false，不生成审批、执行命令或成功记录。

## 核对范围

每个已有或新增服务标明新增、移除、修改或无变化。逐字段展示不可变镜像，以及
test/production的serverId、deploymentName、ports、volumes、secretRefs前后值。
基线有而候选没有的服务明确标“移除服务配置”，但不生成服务器删除操作。
目标变化提醒这可能是迁移而非原地更新；卷变化要求核对备份/数据迁移；涉及对外
监听的端口变化和未解析密钥引用变化另列核对要求。展示的引用仍不是密钥值。

替换/取消任一文件、输入错误、清空或页面导航都会撤销旧下载资格；过期响应不能
恢复旧差异。有效的另一份配置可以暂留页面内存以便重新选择，不会保存到磁盘。
清空或离开页面清除两份配置。下载的review bundle不是可直接导入的manifest；再次
比较应使用原始配置文件或其中明确的manifest字段，而不能把旧review当作授权。

## 固定流程的下一真实接入缺口

这是同一用户配置链路中的确定性变更审阅，而非另一套发布状态机。未来测试请求
必须引用候选manifest绑定，并在批准使用前重新解析和核对，不允许把此reviewDigest
当作人类批准或已执行证明。现有执行库仍需可信适配器提供：

1. 真实Deployment ID和资源所有权；配置文件目前只有声明的Server ID与资源名
2. 完整服务器返回配置及默认值；M12草稿只是部分配置，不能直接替代live配置摘要
3. registry manifest/index digest到目标平台本地image ID的可靠对应，二者不是同一摘要
4. 当前已知执行记录与真实人工验收身份，保留未知结果阻断和已知成功版本回滚规则

本轮没有填造这些证据，没有接入凭据、服务器、执行器或新的真实容器测试，也未
修改既有M10执行路径。下一步应解决这一适配边界，而不是将差异草稿直送生产。

普通单元/真实HTTP/Chrome测试覆盖确定性与绑定、增删和目标/端口/卷/引用差异、
无效任一输入撤销旧导出、取消/重置/迟到响应/重复/导航/390px和明确下载。
