# 让服务部署有明确的输入与结果

SpringBok 把代码仓库、云资源与部署执行连接起来。服务开发者用 SBA 声明如何部署，操作者在控制台选择固定版本、审阅计划并确认，平台协调执行并保留可核对的结果。

## 一条可追踪的部署路径

连接 GitHub 与云账号 → 选择服务与固定提交 → 配置资源和域名 → 预览并确认 → 执行 → 核对回执与实际服务。

SpringBok 的当前重点是部署。Cloudflare Workers 是控制面的运行环境，也是已接通的 SBA 目标；任务状态保存在 SQLite Durable Object 中。自有 NAccount 服务已完成真实部署与管理员登录验收，但这不代表任意应用都已经自动适配。

## 两边各自负责什么

| SpringBok 控制平台 | 你的服务 |
| --- | --- |
| 连接与资源选择、公开配置表单 | 应用构建与依赖锁定 |
| 固定提交、计划预览、用户确认 | 具体发布与数据库迁移 |
| 任务互斥、一次性许可、回执校验 | 备份、数据保留及业务验证 |
| 历史记录和未知结果保护 | 明确的失败边界与可执行修复 |

平台不理解应用的数据库结构，也不通过一次命令退出成功就认定业务可用。外部服务器部署和集中监控属于更广的产品路线；本手册只描述当前代码已提供的 SBA 接入合同。

## 版本与安全边界

本手册面向 manifest v3 与 deployment v2。两份文件独立演进，不能只说“把所有 schemaVersion 改成 3”。预升级是隔离环境中的实际演练，不是普通表单预览；修复是新的明确操作，不是重跑 unknown 任务。

这是公开开发者文档，不是管理控制台。站点不连接你的云账号、不保存部署凭据、不提供在线执行入口。
